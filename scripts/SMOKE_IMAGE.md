# Packaged image smoke test

`pnpm smoke:image --image <local-image> --platform linux/amd64|linux/arm64` validates an already-built Docker image. It does not build, tag, or publish the image. The local image architecture must match `--platform`.

The command checks the production container health endpoint, UID 1001, Node architecture, real native SQLite reads and writes, and the application database's read-only integrity result. Chromium then signs in, changes the initial admin password, confirms the old password fails and the new password works in a fresh session, saves audit retention as 91 days, reloads it, and checks production JavaScript and CSS responses, MIME types, page errors, and same-origin failed requests.

It next creates a uniquely named disposable Kind cluster, installs the Flux CRDs, and runs the same image inside the cluster. Chromium edits a custom manifest in Monaco and checks that the change persists across YAML/form mode switches. Controlled source artifacts and Kubernetes status updates exercise Flux actions, SSE-backed public history, rollback previews, server-side apply previews, schema errors, RBAC denial, and browser rendering/export of preview failures. Preview assertions check that the live spec and resourceVersion remain unchanged.

Requirements are Docker, Node and pnpm dependencies installed from the frozen lockfile, Chromium and its system dependencies (`pnpm exec playwright install --with-deps chromium`), Kind, kubectl, and Flux CLI. The caller needs permission to run Docker and create/delete Kind clusters. Random credentials and cluster config are kept in a private temporary directory; owned containers, child processes, and clusters are cleaned up on success, failure, SIGINT, and SIGTERM.

The image workflow builds one OCI image archive and collects all-severity Trivy JSON reports for each selected architecture. It derives SARIF from those reports, uploads the JSON, SARIF, scan status, and gate summary before enforcing the HIGH/CRITICAL vulnerability gate, then uploads the immutable image archive. Scanner failures, missing or invalid reports, and SARIF conversion failures also block the gate. Both selected scans run even if one fails. The separate Security reporting job uploads available SARIF on non-PR runs even when the gate fails; ARM64 retains the `container-scan` category and AMD64 uses `container-scan/amd64`.

Smoke tests load images from that exact artifact. The publishing job waits for both build scans and smoke tests, verifies the artifact checksums again, then copies that same OCI index to the registry without rebuilding. Pull requests test amd64; branch and release builds test both amd64 and arm64. To run both architectures without publishing, manually dispatch with `verification_only` enabled; it runs both scans and smoke tests and verifies digest-preserving OCI transport through a disposable local registry. Verification-only runs also retain their scan artifacts and upload available SARIF to GitHub Security; they do not publish images.
